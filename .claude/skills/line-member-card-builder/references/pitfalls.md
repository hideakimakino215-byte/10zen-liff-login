# 実際に起きた失敗と対策(10ZEN、2026-10)

## 本番・運用
| 起きたこと | 対策 |
|---|---|
| 毎日のバックアップが権限不足で6日間失敗していた。通知は自分から自分へのメールで、気づかれなかった | 別のアカウントの見張り役(24時間成功がなければメール)。件名でスター・ラベルを付けるフィルタ |
| 大きな SQL を送ると通信が60秒で切れた(3回) | DB に固定コミットのファイルを取得させ、md5 と指紋で確かめて適用(`scripts/make_apply_sql.mjs`) |
| スタッフ画面の手動調整が本番だけ失敗した(WHERE のない UPDATE が安全装置で拒否) | 1行だけの表でも `where id`。関数に WHERE のない更新が無いことをテストで見張る |
| 関数の組み立てが突然失敗した(ライブラリの「最新版」が壊れていた) | 取り込みの版を固定 |
| 古いバックアップが新しい DB に戻せなかった(監査で発見) | 復元の関数を古い形に対応させ、古いバックアップを戻すテストを足す。予行中に戻すときは DOWN を順に |
| パスワード再設定のメールのリンクが開けなかった | Site URL と Redirect URLs を本番の URL に。独自の送信元(SMTP)も本番前に |
| 店の旧システムの QR を読むと旧システムが開いてエラー | 切り替えの日に旧 QR を必ず撤去・差し替え(場所を前日までに確認) |
| 42人同時の試験で、満席の団体が「要確認」になった | 警告の人数を席数から決める(6 → 15) |
| 夜の試験のために受付を24時間にした | 戻す日時を決めて記録し、戻したことも記録 |
| 「登録で 100pt」の案内が、キャンペーン中(200pt)と合わない | 本番開始日にキャンペーンが重なるか、切り替え手順で確かめる |

## 画面
| 起きたこと | 対策 |
|---|---|
| iPhone の LINE で、会員証の表と裏が重なって見えた | 裏返った面を `visibility: hidden` で隠す(3D の裏面の非表示だけに頼らない) |
| 空のままポイントを使うと「nullpt」と出た | 未入力の文を用意し、空・半端・足りない値をテストに入れる |
| 全角の数字のコードを桁違いと判定した | 全角・空白・ハイフンを半角の数字にそろえてから判定 |
| 1回目の結果で、同じ内容とグラフが2回出た | 1回目は「今日の傾向」だけ |
| お席の QR から来た未登録の人が遠回り(3画面+探す) | 機能の画面でその場で「登録して続ける」の1ボタン |
| 会員証の裏に古い機能(外部フォーム)のリンクが残っていた | 新しい機能に置き換えたら、古い入口を全部探して消す |
| 外部レビューで「送れなかったのに『送った』と出る」 | 失敗の種類ごとに文を分け、分からないときは「確認できませんでした」 |

## 進め方
| 起きたこと | 対策 |
|---|---|
| 公開サイトに古い画面が出る | 反映に数分かかる。決裁者に「数分おいて再読み込み」と添える |
| 作業環境から外部サイト(グループ会社のページ)が開けず、URL を検索結果でしか確かめられなかった | 隠さず伝え、決裁者に実機で開いて確かめてもらう |
| テストのブラウザの言語が英語で、日本語のテストが落ちた | テストのページは言語を明示(`ja-JP`) |
| 使い捨て DB が後片付けされず、ディスクを埋めた | 終わったら(失敗・中断でも)必ず消す。ポートを固定しない。最後に残りがないか確かめる |
| 自分のシェルを止めるコマンド(`pkill` の広い指定)で作業が途切れた | プロセスは番号で止める |
| 変数を使った `rm -rf` が安全確認で止められた | 消す場所は文字どおりの絶対パスで書く |
| 新しい関数を DB より先に公開すると、招待からの登録が失敗する組み合わせがあった(監査で発見) | 適用の順番を手順書に書く |
| 文の言葉づかい(治る・効く・改善)を目で探して漏れた | 禁止語の正規表現を全部の文(3言語)にテストで当てる。「有効期限」の「有効」のように正しい使い方を誤検知しないよう、禁止語は細かく |
| 設計を途中で変えた(今日の体調3問 → 毎回の任意チェック) | 設計書に新しい章を足し、古い章の先頭に「〇章が優先」。DB は新しい番号で置き換え |
