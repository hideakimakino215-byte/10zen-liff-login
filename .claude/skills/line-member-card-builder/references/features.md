# 機能ごとの決めることと作りの型

どの機能も「決めること(1問ずつ選択肢つき)」を先に決裁者に聞き、決まったら設計書に日付つきで書いてから作る。下の「10ZEN の決定」は例。

## 目次

## 1. ポイント

**決めること**: 登録・来店のポイント / 1日1回か / 登録した日を来店に数えるか / ポイントの価値(例 100pt=10円)と使用の単位 / 有効期限(表示だけか、自動で消すか)/ キャンペーン。

**作りの型**
- 使用は**お客様が申請 → 会員証に6桁のコード(3分)→ スタッフ画面で入力して確定**。確定するまで減らない。取り消しはお客様もスタッフもできる。
- スタッフ画面は、確定の前に「誰の・何 pt・何円分」を大きく見せ、会計の取り違えを防ぐ。確定の通信の結果が分からないときは「確かめ直す」ボタン(二重確定はしない作り)。
- 店長だけの手動調整・使用の取り消し(理由必須・監査ログ)。
- 全角の数字のコードも受け付ける(スタッフが日本語入力のまま打つ)。
- 空のまま「使う」を押したときなど、未入力の表示(`nullpt` のような崩れ)をテストで見張る。

## 2. ランクと特典チケット

**決めること**: ランクの名前と基準(来店回数の目安を添える)/ 下がるか / 到達のお祝い(1回)/ その後ずっと使える特典 / 期限 / 数え方。

**10ZEN の決定**: 0 / 1,000 / 3,000 / 6,000 / 10,000pt、下がらない。割引(例 毎回5%OFF)は費用が大きいのでやめ、費用の読める物(お茶・デザート)や体験(試食会)に。店で毎回同じに回しにくい特典(優先案内)はやめた。

**作りの型**
- **1回で終わる特典**はチケット(1枚1行・期限・使用済みを DB で管理)。使い方はポイント使用と同じコード方式。
- **来るたびに使える特典**(例 ドリンク無料)は、会員証のランクの色を見せる+POS や注文サービスの0円商品で数える。
- 季節ごとのチケットは「会員×種類×季節」で一意。会員証を開いたときにその季節の分を発行する。
- ランクの色(WHITE OPAL / AMBER / EMERALD / RUBY / ONYX)は会員証・スタッフ画面・店頭 QR で同じにする。
- 停止中の会員のチケット・ポイント使用はスタッフも確定できないようにする(監査で見つかった)。

## 3. 店頭の来店 QR

**決めること**: 受付時間 / 同じ QR での警告人数(席数から)/ タブレットの置き方。

**作りの型**
- 30秒ごとに変わる署名つき QR(architecture.md 5章)。QR 画面は店頭専用アカウント(kiosk)でログイン。**ログインは外さない**(外すと自宅から取れる)。タブレットで最初に1回ログインし、ホーム画面に追加。
- QR 画面には操作できる部品を置かない。会員の特典と使い方を並べて、スタッフへの質問と手書きの POP を減らす。
- 起動時の通信の失敗ではログイン画面に戻らず、数秒ごとにやり直す。長く止まったら「通信を確認」と出して打ち切る。
- 満席を想定した同時アクセスの試験をする(10ZEN: 42人同時でエラー0・遅い人でも約2秒)。

## 4. 店独自の機能(例: 1分体質チェック)

会員証に「また開く理由」を足す機能。10ZEN は薬膳店なので体質チェック。物販店なら肌診断、スクールなら学習の記録など。

**決めること**: 名前 / 問題と答え方 / 判定(同点・全部低い・全部高い)/ 結果に出すもの / 何回でもできるか / 何を保存するか / 同意の文 / 誰がどこまで見るか / 言葉づかいの確認先。

**10ZEN の作り**
- 15問(よくある2点 / ときどき1点 / あまりない0点)+今日の食事の気分。1問1画面・途中から再開。五行ごとの点数を比べ、同点は今の季節を優先、全部1点以下は「バランス良好」、全部同点で高めは「全体的にゆらぎやすいタイプ」(表示だけ)。
- **3段構えの言葉**: 表に出す言葉(「モヤモヤ渋滞タイプ」)/ タップした人だけの正式な名称 / 次の一歩(専門店の相談へ)。
- 来店のたびに任意(スキップ可)。結果は「今日の傾向」と「あなたの体質」(最新3回の平均)。**1回目は「今日の傾向」だけ**(同じ内容を2回出さない)。
- 結果: タイプ名・五角形のグラフ(点数の意味の説明つき)・おすすめの一品・あなたのお茶・季節のひとこと・専門店への案内・**診断ではない旨**。
- 保存: 回答・点数・タイプ・日時(判定を直したら計算し直せるように回答も残す)。初回に同意を取る(スタッフが見ておすすめに使うことも書く)。
- 判定は DB と画面の両方に同じものを持ち、**一致をテストする**。おすすめ表・料理名は差し替えられるデータにする(メニュー未定なら「(仮)」)。
- 教材がある場合: 公開リポジトリには入れず、自前の言葉にした承認済みの内容だけをアプリに入れる。

## 5. Web 版(ログインなし)

- SNS・Google のお店の情報・Web サイトに置く入口。ログインなし・LINE なし。
- 判定は画面の中だけ。**回答をどこにも送らない・保存しない**ので同意は求めない(「保存・送信しません」と表示)。解析タグも入れない。
- 結果の下に LINE の会員証への登録の案内。**結果は会員証に引き継がれない**ことを書く(引き継ぎは同意が要るので後の段階)。
- `?lang=en` などで言語を選べるようにする(英語・中国語の SNS 投稿用)。

## 6. 友だち紹介

**10ZEN の決定**
- 会員ごとに推測できない招待コード(リンクに会員番号を出さない)。LINE の中では `liff.shareTargetPicker`、使えなければ LINE の送る画面とリンクのコピー。
- 招待のリンクから登録すると紹介者が自動で記録される(友だちは何も入力しない)。
- **特典は友だちの初来店のとき**(登録のときではない。登録だけの水増しを防ぐ)。上位ランクの紹介者には代わりにポイント。
- 上限: 暦月5人。自分自身は不可。試験と本番の区分が同じ人どうしだけ。特典は友だち1人に1回。
- お知らせは LINE のプッシュではなく、次に会員証を開いたとき1回(LINE の無料の送信数を使わない)。
- LINE Developers で shareTargetPicker をオンにするのを切り替え手順に入れる。

## 7. 目標と KPI・レジの客数

詳しい型はスキル `store-dashboard-builder` の `references/kpi-and-pos.md`。

**10ZEN の KPI**: 会員来店率(会員の来店 ÷ レジの客数)・新規登録数・機能の実施率・再来店率(直近60日に2日以上)・送客(案内が押された数)。本番開始日の月を1か月目に、3・6・12か月の目標。達成の色は必ずアイコンと文字を添える。
- レジの客数は CSV(文字コード・区切り・列を自動で選び、外れ値を除く)か月の手入力。**客数を取り込んだ日の分だけ**会員の来店も数える(率がずれない)。
- 試験中の客数は試験用として分けて保存し、本番では使わない。
- 店長と閲覧(本部)だけ。スタッフには DOM ごと出さない。

## 8. 月次レポート

- 毎月1日に前の月の集計だけをメール(個人情報なし)。本番開始日の前は送らない。同じ月は1回。取得できないときは所有者に知らせる。
- 見張り役と同じ別アカウントの GAS に置き、レポート専用のトークンで呼ぶ。

## 9. 多言語

**決めること**: どの画面を訳すか(10ZEN: お客様の画面は日本語・英語・中国語(簡体字)、スタッフ画面と印刷物は日本語のみ)/ 固有名詞の表記 / 未確定の名前(料理名)の扱い / 店の住所・電話は訳すか。

**作りの型**
- 文は1つのファイル(`i18n.mjs`)に集め、日本語は既存の文をそのまま参照する。
- 言語の選び方: 画面で選んだ言語(端末に覚える)→ LINE の言語 → 端末の言語。知らない言語は英語、何も分からなければ日本語。
- 途中で言語を変えても、問題の進み具合と結果を保つ(結果はその言語で作り直す)。
- 店頭 QR は切り替えボタンを置かず自動で回す(例 日本語10秒 → 英語5秒 → 中国語5秒。QR は作り直さない)。
- 中国語は全角の記号(，（）：？ · “” ～)に変換する。括弧は言語ごと(日本語 `(…)`・英語 ` (…)`・中国語 `（…）`)。
- テストで: 3言語の項目がそろう・空の文がない・禁止語がない・中国語にかなが混ざらない・英語/中国語の画面に日本語が残らない(例外は決定事項として明記)。
- 翻訳は下書き扱い。ネイティブの確認表(スプレッドシート)と表現チェックを通す。
- 訪日客向けの外部リンク先が日本語しかないときは、近くの対応店舗へ案内し、「サイトは日本語・事前に電話を」と電話のリンクを添える(10ZEN の専門店への案内の例)。

## 10. 注文サービスとの連携(お席の QR)

- お席に QR(`check.html?table=<テーブルコード>`)→ 機能の結果 →「このまま注文する」で、そのテーブルの注文画面を開く。来店ポイントは帰りに付けることが多いので、「来店した日だけ」では足りない。
- お席から来たことは端末の中に数時間だけ覚える(登録で画面を移っても消えない)。
- 読み取った URL は、注文サービスの形・店舗 ID・テーブルコードの形が全部合うときだけ開く(ほかの URL は開かない)。
- 店舗 ID が空の間はボタンを出さない(導入前に出さない)。
- 注文ボタンの上に「通常のメニューです。食材・アレルギーはスタッフへ」。
- 印刷用のページで、同じカードに「すぐ注文の方はこちら」の QR も並べる(LINE を使わない人向け)。

## 11. グループ会社への送客

- 結果画面に「もっと詳しく知りたい方は、○○の相談へ」。押された数だけを数える(誰が押したかは送らない)。
- リンク先は公式の案内ページ(相談の流れ・予約・店舗検索が載っている所)。トップページは仮。
- 共有は集計だけ。実際の相談・購入の数は、案内コードか会員証を見せてもらう形を、相手の会社と決める。
- URL は検索結果だけでなく、**決裁者に実機で開いてもらって確かめる**(作業環境から外部サイトが開けないことがある)。
