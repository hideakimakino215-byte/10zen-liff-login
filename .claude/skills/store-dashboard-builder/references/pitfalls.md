# 実際につまずいたところ(2026-10-14、10ZEN staff.html)

## テストが落ちた

- **「確認しています…」の表示に、結果と同じ ID(`#redeemMsg`)を使った。** テストは `#redeemMsg` が出た瞬間に中身を読むため、結果より先に「確認しています…」を読んで失敗した。**途中経過の表示には別の ID(`#redeemBusy`)を付ける。**
- **文言を飾ると落ちる。** `#rDone` に「✓ 」を足したり、名前と会員番号を別の行に分けたりすると、`/確定しました: 100pt\(10円分\)/` や `/試験 太郎\(user00001\)/` に合わなくなる。アイコンは文言の要素の外(兄弟の要素)に置く。名前と番号を分けて装飾するときは、同じ要素の中の span に分けて、textContent をつなげたときに元の文になるようにする。
- **`#detail` の「数字pt」。** 数字と pt の間に空白を入れない。数字を別の要素に分けるのは可(textContent は空白なしでつながる)。

## はみ出し(横スクロール)

- **grid の列が、入力欄の自然な幅に引っ張られる。** `main{display:grid}` の子は既定で `min-width:auto` なので、`font-size:30px; letter-spacing` の入力欄やプレースホルダーの長さで列が広がり、375px で 130px はみ出した。**`grid-template-columns:minmax(0,1fr)` と、入力欄に `width:100%; min-width:0`** で直る。
- **一覧の行(grid)が数 px はみ出す。** 同じ原因。行の列に `minmax(0,1fr)`、名前に `overflow-wrap:anywhere`。
- **大きい文字のプレースホルダーが途中で切れる。** `::placeholder{font-size:17px; letter-spacing:0}` で入力の文字だけ大きくする。数値の検査では見つからない。写真を目で見る。

## プレビュー(アーティファクト)

- 公開版のビューアーでは **`confirm()` は常に false**、**ファイルのダウンロードは働かない**。`make_preview.mjs` の `-pub.html` は、confirm を常に true にし、CSV をダウンロードの代わりに画面に表示する。
- 公開版には doctype・html・head・body を自分で書かない(公開時に包まれる)。`make_preview.mjs` が外す。
- ロゴの画像は大きいまま埋め込むと重い。幅 360px 程度に縮めてから `--logo` に渡す(Python の Pillow など)。

## 本番まわり

- 本番の関数を更新する前に、本番で動いている中身を読み、リポジトリの基準と一致するか確かめた(一致した)。違ったら止まって報告する。
- クラウド環境から本番の Supabase へ直接の通信は、ネットワークの方針で拒否されることがある。その場合は「外から呼んでの確認はしていない」と書き、関数のログ・DB の記録で確かめる。
- 本番の記録を読んだら、**過去の失敗が見つかる**ことがある(10ZEN では毎日のバックアップが5日間失敗していた)。見つけたことは、聞かれていなくても報告する。
- 「メールが来ない=正常」ではない。見張り役には、実行ログと、データを変えない動作確認(試験メール)を用意する。
- 判定の間隔に注意する。毎朝1回の判定で「36時間以上」だと、実際の通知は最後の成功から約53時間後になる。毎日3時の処理を9時に確かめるなら、基準は24時間にすると、その朝のうちに気づける。

## やり取り

- 承認の確認が一度に十数件出る操作(Gmail のラベルを1件ずつ外す等)は、途中で受け付けられなくなった。まとめて画面で操作してもらうほうが早い。
- Gmail のフィルタを件名の一語(「10ZEN」)だけで作ると、仕事のメールにも当たる。自分発のシステムのメールに絞るなら、件名に固有の語(「バックアップ」「見張り」)を入れる。

## 機械で確かめるコマンド

旧版と新版の要素 ID の差分(`msgBox(..., "id")` のように関数経由で付ける ID は拾えないので、目でも確かめる):

```bash
old=$(git show <基準のコミット>:<画面.html> | grep -oE 'id[=:] ?"[A-Za-z]+"' | grep -oE '"[A-Za-z]+"' | tr -d '"' | sort -u)
new=$(grep -oE 'id[=:] ?"[A-Za-z]+"' <画面.html> | grep -oE '"[A-Za-z]+"' | tr -d '"' | sort -u)
echo "消えた:"; comm -23 <(echo "$old") <(echo "$new"); echo "増えた:"; comm -13 <(echo "$old") <(echo "$new")
```

テストが参照している ID と文言の一覧:

```bash
grep -nE "#[A-Za-z]+|has-text|data-tab|toContain|assert.match" <e2eテスト>.mjs
```
