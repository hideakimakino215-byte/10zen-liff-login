# 目標と KPI の画面・レジ CSV の取り込み(10ZEN の「目標とKPI」タブで学んだこと)

売上・客数・会員などの数字を、目標と並べて見せる画面を作るときの型。10ZEN では「主な KPI 1つ+補助」「目標は開始から 3・6・12 か月の段階」「レジの客数は CSV を端末の中で読む」とした。

## KPI の決め方

- **KPI ごとに「決め方の表」を先に作り、本人に決めてもらう。** 列は「名前(コード)・式(分子 ÷ 分母)・期間の区切り(日本時間の月の1日〜末日。今月は今日まで)・補助の数字」。式が曖昧なまま画面を作らない。
- 主な KPI は1つに絞り、ほかは補助にする(本人が「a を主、b を補助」のように決める)。
- 分母が無い月は率を出さず「—」と理由(例:「レジの客数が未取り込み」)を出す。**0 で埋めない・推測しない。**
- 一部の日だけ取り込んだ月は、分子も同じ日だけで数える(率がずれない)。
- 試験運用の数字と本番の数字は、別の行・別の印で分けて、混ざらないようにする。

## 目標と達成率

- 目標は「開始日からの段階」(例: 1〜3か月目は3か月の目標、4〜6か月目は6か月の目標、それ以降は12か月の目標)。開始日は店長が画面で設定する。開始前は目標なし(灰色)。
- 基準値が無いときは「仮の目標」として入れ、画面で直せるようにする。最初の数か月は「基準を測る」目標なしの KPI があってよい。
- 達成率 = 実績 ÷ 目標。**今月の件数の KPI は目標を経過日数で日割り**して比べる(率の KPI は日割りしない)。
- 色の区分の例: 100% 以上=達成(緑)、80〜99%=あと少し(オレンジ)、80% 未満=未達(赤)、目標なし=灰色。**色だけで伝えず、アイコンと文字を必ず添える。**

## 画面

- 上に KPI のカード(今月の実績・今の目標・達成率)、下に推移のグラフ(目標は破線。データのない月は線を切る)と月ごとの表。
- カードの中に小さな推移のグラフを入れると、スマホでは見づらいと言われた。推移は下のグラフと表にまとめる。
- カードは KPI ごとに色を分け、達成の状況はカードの中の札で示す(色が2つの意味を持たないように)。
- 目標・開始日・取り込みの部品は店長だけ。閲覧の権限には部品を DOM ごと出さない。権限の判定は DB 側。

## レジ CSV の取り込み

- **端末(ブラウザ)の中で読み、サーバーへは必要な列(例: 日付と客数)だけ送る。** 売上など他の列は読まない・送らない・保存しない。
- レジの書き出しは文字コードが様々。UTF-16(BOM あり/なし)・UTF-8(BOM あり/なし)・Shift_JIS を順に判定し、区切りはタブとカンマの多い方を使う。
- 列は見出しの言葉で自動で選ぶ(例: 日付=「日付・営業日・年月日」、客数=「客数・人数」)。「前年・差・客単・率・平均・予算」を含む列は避け、「当年」を優先する。選べないときは画面で選び直せるようにする(レジの種類が店ごとに違うときに必須)。
- 合計・週計・平均の行、空や数字でない値、同じ日付の2回目、未来の日付は飛ばし、**理由と行番号を見せる**。
- 外れ値(0 の日、中央値の3倍を超える日)は既定では取り込まず、本人が確かめて含める。
- 取り込む前に「月ごとの日数・合計・飛ばした行・上書きになる月」を見せて確認を取る。DB は全行を確かめてから書く(1行でも不正なら何も書かない)。同じ日付は上書きし、前後の値を監査ログに残す。
- 上限(1日の値の上限・ファイルの大きさ・1回に送る行数)は、画面と DB で同じ値にする。違うと、画面では通るのに DB がまとめて拒否する。
- 実際のレジの書き出しファイルは、形を確かめるためだけに読む。リポジトリには入れず、テストは同じ形の擬似ファイルで行う。
- 書き出しの種類によっては、欲しい列が入っていないことがある(例: 「注文金額」だけで客数が無い)。そのときは「このファイルには客数がありません」と出して取り込まない。

## API 連携(例: Airレジ)を考えるとき

- API の利用条件(契約・申請・費用)は先方に確かめる。それまでは CSV の取り込みで先に動かし、全体を止めない。
- 自動連携に変えても、画面と DB の決め方は CSV と同じにしておく(取り込み口が変わるだけにする)。
