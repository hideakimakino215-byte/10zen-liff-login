# 決定事項と前提(変えない前提で見てください)

事業責任者がすでに決めたことです。反対意見は「決定事項への意見」として指摘とは分けて書いてください。

## 言葉づかいのきまり(必ず守る)
- 「**治る・効く・改善**」は使わない(英語の cure / treat / heal / improve / effective、中国語の 治疗 / 治愈 / 疗效 / 改善 / 功效 / 见效 も)。医薬品の広告の決まりに合わせるため。
- 体質の結果は「**傾向の目安**」で、**医療的な診断ではない**と必ず書く。
- アレルギーについては「大丈夫」と言わず、**スタッフに声をかけてもらう**。
- 修正案の文言も、このきまりに合わせてください。

## 言語
- お客様の画面(会員証・体質チェック・Web 版・店頭の QR)は 日本語・英語・中国語(簡体字)。
  - LINE の言語で自動で選び、画面の上の「日本語 / English / 中文」でも切り替えられる(端末に覚える)。
  - Web 版は URL の `?lang=en` / `?lang=zh` でも選べる。
- **スタッフ画面・お席の QR カード(印刷物)は日本語のみ。**
- 英語の固有名詞は「**Nihondo**」(薬日本堂)・「**Gojun Tea**」(五巡茶)。
- **お料理の名前は、メニューが決まるまで日本語のまま**(英語・中国語ではその旨の注記を添える)。名前の「(仮)」も確定まで残る。
- 店の住所・電話番号は日本語のまま。
- 翻訳の文そのものは、別途ネイティブの確認中(明らかな誤り・不自然さの指摘は歓迎)。

## 店頭の QR 画面(タブレット)
- **ログインが必要**(外すと自宅から来店ポイントを取れてしまうため)。タブレットで最初に1回だけログインし、あとは開くだけ。
- QR を表示している画面には、**操作できる部品(ボタン・リンク・入力)を置かない**(お客様が触っても何も起きないように)。
- 言語は **日本語10秒 → 英語5秒 → 中国語5秒** で自動で切り替わる(切り替えボタンは置かない)。QR は30秒ごとに変わる。

## 見た目
- 会員証の世界観: 和紙色の地・明朝体の見出し・**生薬の水彩イラスト**・ランクごとの枠の色(WHITE OPAL / AMBER / EMERALD / RUBY / ONYX)。承認済み。
- 五行の色: 木=緑・火=赤・土=黄土・金=灰・水=紺(体質のタイプ名・五角形のグラフ・スタッフ画面の印で共通)。
- スタッフ画面は、お客様の画面とは別のすっきりした業務用の見た目(機能ごとに色分け)。承認済み。
- 会員証の体質チェックの欄は、初めての方にはボタンだけ(見出しなし)。

## ポイント・ランク・来店
- 100pt = 10円。使うときは会員証に出る **6桁のコード(3分有効)** をスタッフ画面で入力して確定。
- 来店ポイントは店頭の QR を読んで1日1回。**受け付けは 11〜21時**(時間外は「対象外です」と出るのは仕様)。
- ランクは累計ポイントで上がり、下がらない(1,000 / 3,000 / 6,000 / 10,000pt)。
- 同じ30秒の QR で15人以上が来店記録すると、スタッフ画面に「要確認」(QR の写真の拡散の疑い)。

## 体質チェック
- 15問(よくある / ときどき / あまりない)+今日の食事の気分。1問1画面。途中でやめても続きから。
- 結果の名前の例: 「カッカ熱こもりタイプ」。「あなたにおすすめの五巡茶」という見出しは決定済み。
- 1回目は「今日の傾向」だけ。2回目から「あなたの体質(最新3回の平均)」と「これまでのチェック」が出る。
- お席の QR から入った人には、結果のすぐ下に「このまま注文する」(注文はダイニーという別の注文システム。未設定の間は出ない)。

## スタッフ画面の権限
- 店長: すべて(手動のポイント調整・目標と KPI を含む)。スタッフ: ポイント使用・会員・集計・体質チェック。閲覧(本部): 見るだけ。**閲覧には個人の体質を出さない。**
- スタッフ画面にはスタッフ自身のスマホでもログインする。

## 既知の保留(指摘は不要。より良い案があれば歓迎)
- 期限切れのコードを入れたときのスタッフ画面の文言が一般的(サーバー側の変更が要るため保留)。
- 会員の検索はひらがなの読みに対応していない。
- Web 版の体質チェックの結果を、LINE 登録後の会員証に引き継ぐ機能はまだない。
- パスワード再設定のメールは、送信元の設定(本番開始前に行う)が済むまで届かない。

## 画面集の見方
- 撮影はテスト用の擬似データ(名前・番号・日付はテスト用)。会員番号が `user0000x` なのはテスト環境のため(本番は `AO`・`T` で始まる)。
- 目標と KPI(F-9)は、擬似データのため空欄が多い。
