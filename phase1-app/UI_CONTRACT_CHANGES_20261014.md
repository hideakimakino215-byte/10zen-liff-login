## CSV の仕様(#9)

- 氏名・LINE ID は含めない。先頭が `= + - @` の文字列は数式として解釈されないように加工する。未取得の値は空欄にし、0 で埋めない。
- **集計のスナップショット:** `staff_dashboard` の全項目を1行。1列目は集計の時刻。
- **会員別の利用状況:** `staff_list_members`(100 件ずつ全件)の後、会員ごとに `staff_member_detail` を順番に呼ぶ。
  - **厳密な同一時刻のスナップショットではない。** 「取得開始時刻」を列に記録する。
  - 台帳は直近 100 件まで。100 件以上ある会員は「集計は不完全」と明示する。
  - 来店日は `visits` を返す API がないため、台帳の「来店ポイント付与」の日付で代用する(列名に明記)。
  - 会員ごとに閲覧の記録(監査ログ `view_member`)が残る。実行前に確認ダイアログを出す。

## 店頭タブレットの QR 画面(qr.html)

- **決定:** 牧野さん(2026-10-14)。ポイント・ランクは自作の会員証で続ける(ダイニーのポイント機能はオフにする)。そのため来店 QR の画面も B案に合わせた。
- **見た目:** 白地+ティール(ポイント使用と同じ色)。左に「10ZEN の LINE 会員証」・会員の特典3つ・使い方3手順(番号を縦にそろえる)、右に QR。縦置き・スマホ幅では1列。QR が切り替わるまでの残り時間を細い帯で表示。
- **ねらい(牧野さん、2026-10-14):** スタッフへの問い合わせ(「これは何?」「会員になると何がある?」)と、手書きの POP の貼り出しをなくす。画面だけで「何か・何がもらえるか・どうするか」が分かるようにする。
- **お客様に見せる数字:** 来店ごとに 100pt(1日1回)、登録で 100pt、100pt=10円、ランク特典の例(季節の薬膳茶・限定スイーツ)。DB の設定(point_rules・app_settings)と会員証の特典に合わせる。食い違いは自動テスト `tools/test_kiosk_copy.mjs`(3件)が検出する。期間限定のキャンペーンは常設の画面に書かない。
- **守っていること(自動テストが確認):** QR 表示中は操作できる部品(ボタン・入力・リンク)が 0 個。`#qrImage` の中の SVG は1つ。URL の文字(`#qrUrl`)は画面に出さない。通常のスタッフのアカウントは `#msg` に「店頭QR専用」を含む文言で拒否。ログインは `#email` `#password` `#login`。
- **追加:** 店頭のタブレットが眠らないよう、画面のスリープを防ぐ(使えない端末では何もしない)。
- **テスト:** 156 件すべて合格(文言の食い違いの検査 3 件を追加)。擬似データのプレビューで、タブレットの横置き・縦置きは1画面に収まり、スマホ幅も含めて横スクロールなし・ブラウザのエラーなしを確認。本物の環境での実機確認はまだ。
- **見た目の改訂(2026-10-15、案):** お客様が見る画面なので、スタッフ画面の B案(白地+ティール)ではなく、**会員証と同じ世界観**(和紙色の地・明朝の見出し・水彩の生薬・ランク色の枠)にした。**会員証そのものの見本**を大きく見せ、ランクの色が数秒ごとに変わり、そのランクの特典を下に出す(動きを減らす設定の端末では変えない)。見出しは「スマホに、10ZEN の会員証を。」。横置き・縦置きとも1画面に収まる。ティールの版はコミット f62d868 に残っている。牧野さんの確認待ち。
